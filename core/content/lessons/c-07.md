## Before structures: names do not establish validity

You need [objects and pointer access](/learn/c/5/) and [function contracts](/learn/c/6/). A struct groups fields describing an entity. The field names help readers, but no automatic rule says that a capacity is supported, an enable flag is Boolean, or a replica count fits the available nodes. Domain constraints must be stated and checked.

The reference assigns capacity_mib=512, enabled=1, parity=1. Its `valid` expression checks only capacity>=256 and enabled==1. That limited predicate is deliberately not a complete RAM-controller validation: it has no upper capability bound and does not check the parity field. Identify exactly what a check establishes before treating its name as proof.

## Derive a cross-field contract

For a server profile, let nodes range from one to sixty-four, replicas from one to nodes, and enabled be zero or one. Testing each field against an unrelated integer width is insufficient. Replicas seven and nodes six are individually representable, but cannot describe seven distinct copies on six nodes.

Try this example in the terminal beside the documentation.

```c run:struct-validation
#include <stdio.h>
struct Profile {
    int nodes;
    int replicas;
};
int main(void) {
    struct Profile profile;
    profile.nodes = 6;
    profile.replicas = 7;
    int valid = profile.nodes >= 1 && profile.nodes <= 64 &&
                profile.replicas >= 1 && profile.replicas <= profile.nodes;
    printf("nodes=%d replicas=%d valid=%d\n", profile.nodes, profile.replicas, valid);
    return 0;
}
```

Expect `nodes=6 replicas=7 valid=0`. Change replicas to three and predict one. Validation remains about a requested profile; it does not create durable copies or verify data consistency.

## Layout belongs to an implementation contract

Native C preserves member declaration order but can insert padding. A controller register layout or wire packet therefore needs documented offsets, widths, alignment, and byte order. Casting an arbitrary byte buffer to a struct can introduce alignment, representation, and aliasing assumptions that the field names do not justify. Encoding fields explicitly is often the clearer boundary.

The teaching interpreter stores named model fields and does not supply ABI-accurate structure layout or general aggregate-by-value semantics. Do not infer native `sizeof(struct ...)` behavior from its object display. For real device interfaces, use the platform's documented accessors and layouts. [Resource and failure-domain foundations](/learn/device/6/) explain the non-language rules behind server profiles; [register contracts](/learn/device/1/) explain how to publish a validated profile.

## A structure gives fields a relationship
A struct groups named members into one type. It is useful when several values describe one entity: a memory module has a capacity, an enable state, and an error-control mode. Three unrelated scalar variables can hold those values, but a structure makes their relationship part of the program's vocabulary.

`struct RamConfig` in the editor contains capacity_mib, enabled, and parity. Dot access selects a member from an object: config.enabled reads one field. Arrow access selects a member through a pointer: p->enabled is equivalent in meaning to accessing the pointed-to structure and then its member. Neither notation automatically validates a legal configuration.

## Layout is a separate concern
Native C lays structure members out in declaration order, but an implementation can insert padding to satisfy alignment. Consequently, summing member sizes does not always give the total structure size. A raw struct memory dump is not a portable network or file format. An external binary format should specify field widths, byte order, and offsets explicitly and encode them intentionally.

The embedded interpreter models structures as named virtual fields rather than claiming an ABI-accurate packed byte layout. Its sizeof support covers scalar and array lessons; it does not promise full native structure-padding behaviour. That distinction prevents the convenient learning view from becoming a false model of a compiled target.

## Validate the contract
The editor populates the three configuration fields and checks that the capacity is at least 256 MiB and the enable flag equals one. It prints capacity 512 and a valid result of one. The calculation is about requested settings. A real controller's capabilities, legal timing parameters, training procedure, and feedback are additional information that this structure alone does not contain.

Change enabled to two. The field can physically hold that integer, but the stated Boolean-like contract rejects it. Change capacity to 128 and watch the validation fail. A type often rules out broad categories of error, while explicit checks establish narrower domain rules. Both are needed.
