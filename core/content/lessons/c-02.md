## Before integer operations: declare the domain

Review [fixed-width machine arithmetic](/learn/machine/4/) and [C objects](/learn/c/1/). A native C type has implementation-defined size subject to the language's requirements. This model chooses a 32-bit int and unsigned int. Those choices let us inspect representation, but they are not a universal claim about every C target.

An unsigned 32-bit object holds magnitudes 0 through 4294967295. An int in this model holds -2147483648 through 2147483647. The C language defines modular unsigned arithmetic; signed overflow is undefined behavior in native C. The teaching engine reports the signed overflow to make the invalid assumption visible. Observe the language rule before extrapolating from a wrapping processor instruction.

## Flags are positions rather than a magnitude

In the reference, bit zero and bit two are independent flags. Their numeric masks are 1 and 4. `flags | 1U | 4U` combines selected positions into five. `(flags & 4U) != 0` returns a Boolean-like integer one. A test written only as `flags & 4U` returns four, which is true in a condition but is not the promised integer one. API output shape is part of the contract.

Logical `&&` short-circuits and interprets each operand as true or false. Bitwise `&` evaluates the bit pattern operation. For example, `2 && 1` is one, while `2 & 1` is zero. That difference becomes crucial when a guard prevents a division or invalid access.

## Try both width boundaries in the terminal beside you

```c run:unsigned-wrap
#include <stdio.h>
int main(void) {
    unsigned int value = 4294967295U;
    value = value + 1U;
    printf("wrapped=%u\n", value);
    return 0;
}
```

Expect `wrapped=0`. Then load the deliberate signed failure:

```c run:signed-overflow
int main(void) {
    int value = 2147483647;
    value = value + 1;
    return 0;
}
```

Expect a signed-overflow error. Do not describe that diagnostic as a requirement that every native C build must stop; native behavior after undefined overflow is not guaranteed.

Bit clearing uses `flags & ~mask`; toggling uses XOR. Shifts require a valid count, and signed left shifts have further native restrictions. Use an explicitly unsigned value for a bit-field experiment and keep the shift in 0 through 31. For a real device, arithmetic validity still does not establish allowed register behavior: [device contracts](/learn/device/1/) add permissions, reserved bits, and side effects.

## Try this in the terminal beside the documentation

The following is a complete program for this page's engine. Load it into the terminal beside this explanation, predict the result, then press Run. Open **State** for final values, **Trace** for recorded execution, and **Encoding** for emitted bytes when this engine supplies them.

```c run:reference
#include <stdio.h>
int main(void) {
    unsigned int flags = 0U;
    flags = flags | 1U | 4U;
    printf("flags=%u enabled=%d\n", flags, (flags & 4U) != 0);

}
```

## Storage width is a constraint
A type tells C how operations and stored values are interpreted. This interpreter models int as 32-bit signed and unsigned int as 32-bit unsigned. char occupies eight bits and short sixteen. The fixed-width names uint32_t and int32_t express the intended width directly. On a real target, consult the implementation and use sizeof rather than assuming every type has the model's size.

Unsigned 32-bit arithmetic is modulo 2^32. The maximum is 4294967295, so adding one gives zero. Signed overflow has a very different rule in C: it is undefined behaviour. The interpreter deliberately reports a signed-overflow error instead of silently wrapping. A compiler can exploit the assumption that a valid signed operation does not overflow; that is why observing one processor's wrapping ADD does not establish a C guarantee.

## Literal and conversion rules
A suffix U requests an unsigned integer literal. In the editor, `0xffffffffU` explicitly represents an unsigned bit pattern. Assigning values to narrower types can discard high bits according to the model's documented conversion behaviour. Such conversions should be intentional: a wire protocol's one-byte field needs a validated range before conversion, not a hope that truncation is harmless.

The usual arithmetic conversions decide how two numeric operands are combined. The teaching subset preserves unsignedness for its 32-bit arithmetic. It intentionally excludes floating point, long-width differences, and several full-C conversion details. Those limits are recorded so you do not infer broader compliance from a passing example.

## Pack independent flags
The example starts at zero, sets bits zero and two with bitwise OR, and tests bit two using AND. The flag word becomes 5, binary 0101. The comparison with zero turns a nonzero mask result into a logical one. Bitwise `&` processes bits; logical `&&` tests truth values and short-circuits evaluation. They are different operators even when a small example happens to produce the same value.

## Predict, run, and break it
Check that the printed flag word is 5 and the test result is 1. Change the mask to 2 and predict the test result. In a separate run, create `int x = 2147483647; x = x + 1;` and observe the signed-overflow error. Then use an unsigned value with the U suffix and verify the defined wrapping result.
