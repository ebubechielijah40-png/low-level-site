## Before a counter: distinguish a numeric value from a character

You need [x86 byte registers](/learn/os/1/) and [string output](/learn/os/2/). Integer seven has a different bit pattern from ASCII character '7', whose byte code is 55. The BIOS teletype service accepts one character; it does not format a general integer for you.

The reference initializes CX=10 and AL=48. Each iteration prints the current character, increments AX, then LOOP decrements CX and branches if the new count is nonzero. Exactly ten character codes, 48 through 57, produce `0123456789`. Incrementing all of AX is safe for this restricted sequence because AL never crosses 255 and changes AH. That precondition must be explained before generalizing the routine.

## Derive the body-first boundary

If CX starts at one, the body prints zero once and LOOP changes CX to zero, so execution leaves the loop. If CX starts at zero, the body still executes before LOOP. The decrement wraps a sixteen-bit zero to 65535, and the branch repeats. The initial zero is not a request for zero body executions in this structure.

## Try a zero-entry guard beside the explanation

```boot run:zero-count
bits 16
org 0x7c00
mov ax,0
cmp ax,0
je done
mov ah,0x0e
mov al,48
int 0x10
done:
hlt
```

Expect no console output. The comparison selects the exit before the output operation. This is a small entry-guard demonstration using AX because the supported boot assembler has limited comparison forms; it does not claim a full x86 numeric-formatting library.

## Output conversion has an algorithm and a bound

For a multi-digit decimal integer, you must obtain decimal digits and output them in the right order, often using repeated quotient/remainder division and a temporary buffer or stack. The restricted boot assembler does not implement the general division instruction sequence needed for that full routine. Do not paste an unsupported native algorithm and mistake the tool's rejection for a language restriction.

Use **Trace** to count ten firmware output calls and inspect final CX=0 for the reference. Then change the initial count to one and verify the new prediction. Changing it to zero can reach a budget or unsupported firmware-service error as AX progresses; the relevant fact is that the algorithm did not perform zero iterations. Identify that earlier cause rather than attributing the failure merely to the final diagnostic.

## A tiny program still has an algorithm
The editor prints decimal digits zero through nine. It sets CX to ten iterations, AH to the teletype service, and AL to ASCII 48, the code for character zero. Each iteration outputs AL, increments AX, and executes LOOP. LOOP decrements CX and branches while its new value is nonzero.

Incrementing AX rather than AL works here because the low byte stays below 255 throughout ten iterations, so no carry changes AH. That is a reasoned precondition, not a general equivalence. If the low byte crossed 255, AX's high byte would also change and could select another firmware service.

## Data and its encoding
The numeric integer 7 is not the same byte as the displayed character '7'. ASCII digit characters occupy codes 48 through 57. Adding 48 maps a single numeric digit zero through nine to its character code. Printing a multi-digit number requires a conversion algorithm, often repeated division by ten and reversed output order. Firmware teletype does not perform that conversion for you.

The earlier RISC-V teaching ECALL service 1 accepted an integer and formatted it. Here the BIOS service accepts one character. Different environments expose different abstractions. The instruction set alone does not provide a general decimal printer.

## A visible result and an internal argument
Run the editor and expect `0123456789`. Trace should contain ten output calls and a final HLT. CX ends at zero. The sequence proves the emulator is responding to instructions and state, while the boundary checks establish the run remained inside its permitted image and stack ranges.

Change CX to one, then zero. A zero initial count on x86 LOOP wraps the sixteen-bit counter when decremented, so it does not mean "do zero iterations" in this body-first arrangement. The emulator's execution budget should stop the unexpectedly long run. This is a concrete reason to examine the position of a loop's condition rather than assume all loop syntax shares one entry rule.
