## Before arrays: distinguish capacity, length, and position

Review [load/store addresses](/learn/machine/5/) and [C loop bounds](/learn/c/3/). An array is an object containing a fixed number of elements. A used length may be smaller than its allocated capacity. An index selects one element. The valid comparison is against the relevant logical length, and the object capacity remains a separate upper bound.

For four model ints, the object has sixteen bytes. Element i is reached at the base plus `i*sizeof(int)`. Valid indices are zero through three; the address one past the object can be useful for stopping, but dereferencing it is invalid. A numeric address being mapped does not grant permission to read outside the C object.

## Derive the reference without relying on a loop

The initializer creates four elements 4, 8, 12, 16. `sizeof(values)` is sixteen and `sizeof(int)` four in this environment, so the computed length is four. The loop sums each object element exactly once. The independent expected result is 4+8+12+16=40. Inspect the array and sum in **State / variables**, then inspect the visited indices in **Trace** or add diagnostic prints.

That sizeof ratio is appropriate while values names the array object. In an ordinary function parameter, an array declaration is adjusted to a pointer; its sizeof does not recover the caller's count. Pass a length explicitly. The C VM has a limited sizeof model and is not a complete native type system, so use the stated scalar/direct-array examples rather than inferring every ABI layout.

## Try the one-past access as a deliberate failure

```c run:array-boundary
#include <stdio.h>
int main(void) {
    int values[4] = {4, 8, 12, 16};
    printf("%d\n", values[4]);
    return 0;
}
```

Try this in the terminal beside the documentation. Expect a bounds error. The teaching diagnostic identifies the violated object contract. Native C does not promise to diagnose the same access; out-of-bounds behavior is undefined even when an adjacent address can be read.

Real packet, device, and file buffers add another obligation: validate lengths before indexing, copying, or multiplying counts into byte sizes. A request for 1024 elements needs space for 1024 times the element width, and that multiplication can itself overflow. Buffer capacity is not proof the received message actually contained every field you want to parse. [Protocol foundations](/learn/device/5/) extend this distinction to block and network formats.

The following is a complete program for this page's engine. Load it into the terminal beside this explanation, predict the result, then press Run. Open **State** for final values, **Trace** for recorded execution, and **Encoding** for emitted bytes when this engine supplies them.

```c run:reference
#include <stdio.h>
int main(void) {
    int values[4] = {4, 8, 12, 16};
    int length = sizeof(values) / sizeof(int);
    int sum = 0;
    for (int i = 0; i < length; i++) {
        sum += values[i];
    }
    printf("length=%d sum=%d\n", length, sum);

}
```

## One name describes several objects
An array has a fixed number of contiguous elements of one type. `int values[4]` creates four int elements. Valid indices are 0, 1, 2, and 3. The length is four, but index four refers to a position immediately after the final element. Indexing begins at zero because the address calculation is base + index × element size; element zero has zero offset from the base.

In this model each int occupies four bytes, so four elements occupy sixteen bytes. `sizeof(values)` reports the array's total size, while `sizeof(int)` reports one element's size. Their ratio gives the element count when values is still an array object in that scope. When an array is passed to an ordinary C function, it generally decays to a pointer; sizeof that pointer does not recover the original array length. Pass a length explicitly.

## Separate physical and logical bounds
Real C does not generally check array indices at runtime. Reading outside an array's bounds is undefined behaviour, even if the numeric address is inside mapped memory. Our educational interpreter reports an out-of-bounds access to make the mistake visible. That helpful diagnostic is a feature of the runner, not a guarantee that a native C binary will stop safely.

The example has values 4, 8, 12, and 16. It walks indices smaller than the length and computes 40. The independent expected sum is simply 4 + 8 + 12 + 16. Inspect the Variables tab to see the unchanged array and the resulting scalar sum. Array inspection is a structured view of the model, not a raw dump of host memory.

## Change one assumption
Set the condition to i <= length and run again. The last access attempts index four and fails. Change the initial index to one and the program misses the first value. Change the array's element count while leaving the loop's literal bound at four and consider whether the loop still describes the intended object. The relationship between a buffer and its length must remain explicit.
