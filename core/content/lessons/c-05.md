## Before pointers: follow object identity

You need [C objects](/learn/c/1/) and [array bounds](/learn/c/4/). A pointer value gives an access path to an object or a position in an object. Copying the pointer copies that path, not the referenced object. Lifetime, alignment, type compatibility, and permitted bounds remain obligations even if the bits look like a plausible address.

In the reference there is one integer object named value and one pointer object named p. Initializing p with `&value` makes it designate that integer. `*p = *p + 21` reads the referent, computes a new value, and writes the same object. Later reads through both value and *p therefore see 42. The pointer object itself was not reassigned.

## Try a copy and an alias beside the documentation

```c run:copy-alias
#include <stdio.h>
int main(void) {
    int value = 21;
    int copy = value;
    int *alias = &value;
    *alias = 42;
    printf("value=%d copy=%d alias=%d\n", value, copy, *alias);
    return 0;
}
```

Expect `value=42 copy=21 alias=42`. The unchanged copy demonstrates separate identity. The matching value and alias demonstrate a shared referent. Inspect **State / variables**: the pointer view describes a virtual object and index rather than inventing a native laptop address.

## A lifetime ends even if the old bits remain

Returning `&local` from a function does not keep that local alive. An address-like value can outlive the object it once designated. The interpreter reports use of a dead model object, while native C does not guarantee a useful diagnostic. Similarly, an uninitialized pointer has no established referent, and a one-past array pointer must not be dereferenced.

Native pointer arithmetic advances in elements of the pointed-to type. Adding one to an int pointer advances by one int, not one byte. It is permitted only within the same array object or its one-past position under the language rules. This is stronger than checking whether the numeric address falls somewhere inside RAM.

A device register address adds a different contract. A cast from integer 0xF000 to a native pointer neither maps a controller nor grants access permission. The site deliberately requires mmio accessors for its virtual device window and disallows raw host-address casts. [Address-space foundations](/learn/device/1/) explain why CPU virtual, physical, and DMA addresses must not be conflated. Rust's later borrowing rules add an explicit access policy to the aliasing problem you can already observe here.

## A pointer answers where
An ordinary integer value can answer "how many?" A pointer identifies an object or a location within an object. `&value` obtains a pointer to value; `*pointer` accesses the object reached through that pointer. The symbols are context-sensitive: `*` between numeric expressions multiplies, while unary `*` performs indirection.

The declaration `int *p` says p is a pointer to int. It does not create a second int object automatically. In the editor, p is initialised with &value, so both the name value and the expression *p designate the same object. Assigning through *p therefore changes what later reads through value observe. This shared identity is called aliasing.

## Reference is not copy
If you instead write `int copy = value`, copy is a separate integer object. Changing copy does not change value. If you write `int *other = p`, the pointer is copied and both pointers reach the same original object. The difference between copying a value and copying a reference is central to data structures, APIs, and ownership models.

Real C pointers also have object-lifetime and alignment requirements. A pointer to a local object is invalid after that object's lifetime ends. An uninitialised pointer has no valid target. A pointer can point one element beyond an array for certain arithmetic comparisons, but dereferencing that position is invalid. The teaching runner limits pointers to virtual objects and does not provide host addresses or arbitrary memory access.

## Follow the example
The program sets value to 21, creates p = &value, and writes *p = *p + 21. It then prints value and *p. Both are 42 because both accesses read the same cell. The Variables tab displays a pointer's index and virtual object length, deliberately avoiding a misleading host-address display.

Explain why both original access paths now observe the new result. For an array, a pointer passed from the array base can advance element by element inside the declared bounds.
