## Before C: keep syntax, semantics, and execution separate

You can start reading C here, but [assembly and register effects](/learn/assembly/1/) provide the reason this track follows machine code. A source program describes operations under a language's rules. A native compiler translates those operations into target instructions; a linker combines objects and resolves symbols; a loader establishes an execution environment. None of these stages is identical to the source text being accepted by a parser.

This site's C terminal interprets an AST, an abstract syntax tree. It parses supported syntax and executes a bounded virtual model of objects and control flow. It does not invoke GCC, emit machine instructions, or expose the server's native addresses. Its **Trace** describes interpreter work, and its step count is not a processor-cycle count. **Encoding** therefore has no native C image to display.

## Explain every part of the first program

`#include <stdio.h>` selects recognized output declarations in the teaching environment. Native preprocessing would provide header contents before compilation; here approved header names are handled locally. `int main(void)` declares the entry function, a returned integer, and no parameters. Braces delimit its body. The semicolon terminates the call statement. `return 0` completes the entry with a success code.

`printf` receives a string literal. Its characters are data, not instructions. The `\n` escape represents a newline character, rather than the two printed characters backslash and n. The output service formats and appends text through the environment. A CPU ADD instruction has no built-in ability to format decimal or display a browser console; a runtime interface supplies that behavior.

## An object stores a value; a name selects it

Try this second complete program in the terminal beside the documentation.

```c run:object-update
#include <stdio.h>
int main(void) {
    int value = 5;
    int old_value = value;
    value = value + 3;
    printf("old=%d current=%d\n", old_value, value);
    return 0;
}
```

Expect `old=5 current=8`. The initializer copies five into a second object. The later assignment reads value, calculates eight, and stores it back; old_value remains five. A variable does not retain a reactive expression linking it to its initializer. In **State / variables**, identify the two separate values.

Delete a semicolon to observe a parse-stage error. Rename main to observe an entry-point error. Use an unsupported host function to observe the runner's interface boundary. Those are distinct from a valid program computing the wrong value. The next lessons supply arithmetic, bounds, lifetime, and function contracts so that your correctness claim can extend beyond “it runs.”

## Why add a language above assembly?
Assembly exposes every instruction, which is excellent for observing machinery but costly for expressing large programs. C adds types, expressions, functions, and structured control flow. A compiler chooses instructions that implement those constructs for a target architecture. The same C source can compile to different instructions on different processors. The types and language rules constrain that translation.

C is a systems language, but its abstract machine is not identical to any processor. An optimiser may remove a variable, keep it in a register, or combine operations. "A variable is always a fixed RAM location" is therefore an incomplete explanation. What C guarantees is the behaviour of valid programs under its language rules, including the observable effects defined by the standard.

## Read a minimal program
`#include <stdio.h>` supplies declarations for standard input/output functions. `int main(void)` defines the entry function for a hosted C program and states that it accepts no arguments. The braces enclose a compound statement. `printf` uses a format string to describe output; `\n` is a newline escape. `return 0` reports successful termination to the runtime. Falling off the end of main also returns zero in modern C; an explicit return is useful here but is not a universal validity requirement.

On a real hosted system, startup code calls main after preparing the process. The operating system does not simply jump to the C function as though it were an instruction label. A freestanding kernel has different startup arrangements; the included native kernel example introduces those later.

## What Run means on this site
The editor parses C into a syntax tree and interprets a bounded teaching subset. It supports integer expressions, branches, loops, functions, arrays, structures, pointers to virtual objects, and a few output/device functions. It does not compile to native code. There are no file, shell, network, dynamic allocation, or host-pointer APIs. The Runner reference lists the exact supported forms. Unsupported syntax produces an error rather than fabricated output.

The model uses four-byte int and pointer sizes, one-byte char, and two-byte short. Those are explicit model choices. Real C implementations may have different widths; fixed-width types and sizeof are tools for expressing and checking requirements.

## First experiment
Run the editor and expect `Hello, machine.` followed by a newline. Change the text, add a second printf, and observe output order. Delete the semicolon after the call to see a parser error. Replace the entry function name to see the missing-main diagnostic. These failures occur at different stages: syntax recognition and entry-point selection.
