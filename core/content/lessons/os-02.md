## Before a boot string: account for code, data, and addresses

You need [the x86 boot contract](/learn/os/1/) and [byte addressing](/learn/machine/3/). A label assigns a symbolic address. `db` emits data bytes; it does not execute a string-print instruction. Instructions use that address to read bytes one at a time. Control must stop or jump before reaching the data as if it were code.

Under a conventional real-mode address calculation, DS:SI reaches segment times sixteen plus the offset. With DS zero in our limited model, SI can hold an address near 0x7C00 directly. The reference clears AX, writes zero to DS, and initializes SI with message. A native boot implementation must establish the intended segment state and direction flag rather than relying on emulator presets.

## Derive the loop's stopping rule

LODSB reads the byte at DS:SI into AL and advances SI forward in this environment. CMP AL,0 updates the zero condition. JE takes the branch for the terminating byte. Otherwise INT 0x10 outputs AL and JMP repeats. The zero terminator is consumed but not printed. AH stays 0x0E across these low-byte updates.

The source's 13 and 10 encode carriage return and line feed. They affect the displayed line movement. They are not the decimal characters “13” and “10,” and they are not part of the text's English words. Encoding requires distinguishing stored numeric bytes from printed representations of numbers.

## Try a fully prepared short string beside you

```boot run:short-string
bits 16
org 0x7c00
xor ax,ax
mov ds,ax
cld
mov si,message
mov ah,0x0e
again:
lodsb
cmp al,0
je done
int 0x10
jmp again
done:
hlt
message:
db "BITS TO BOOT",0
```

Expect `BITS TO BOOT`. CLD explicitly selects forward string traversal in real x86; the site's model already uses forward traversal and does not implement every direction-flag behavior. The instruction still records an important native assumption rather than hiding it.

## Bounds are supplied by the object contract

A terminator-based string requires reachable zero within a valid data region. Removing it does not promise a parser error: subsequent padding can contain zeros, and the output may appear unchanged despite reading beyond the intended string. State the object's length or termination guarantee before claiming the traversal is safe. A valid model memory address is weaker than belonging to the intended object, as the assembly array lesson showed.

Inspect **Trace** for the last byte read and the taken completion branch. Save an image, reimport its bytes, and boot the saved image separately from the source. That comparison establishes what the produced artifact does under the emulator's contract without assuming the editor reconstructs source from machine bytes.

## The image contains code and data
A boot sector can hold both instructions and literal bytes. A label such as message names the address of its first data byte. The directive db emits bytes; the CPU does not execute it as a mnemonic. If control accidentally falls into that data, it will try to decode the same bytes as instructions, often with unintended results.

Our example reserves a zero byte after the message. That byte is a terminator, not a printed character. The loop loads a byte, compares it with zero, and stops when the terminator is reached. A string's length therefore depends on its contents under this convention. Missing a terminator can cause the code to walk into adjacent data.

## Real-mode address preparation
Real-mode addressing uses segments and offsets. A physical address is normally segment × 16 + offset, subject to the architecture's addressing details. The emulator supports a deliberately limited zero-segment configuration, so DS is set to zero and SI contains an address near 0x7C00. Real BIOS code must not assume every incoming segment register or stack setting is already suitable.

`xor ax,ax` clears AX. `mov ds,ax` chooses zero for the data segment. `mov si,message` places the string's offset in SI. `lodsb` reads a byte through the DS:SI convention and advances SI in the model's forward direction. AH remains 0x0E for the firmware output service.

## Trace one iteration
At print, LODSB places the next message byte in AL. CMP AL,0 sets the model's zero condition. JE done takes the branch for a terminator; otherwise INT 10h outputs the character and JMP print repeats. The output includes carriage return and line feed bytes where the message specifies 13 and 10. The screen renderer handles these as line movement rather than showing their numeric codes.

Run and inspect Trace alongside the screen. Find the final LODSB of the zero byte and the conditional jump that ends the loop. The expected message identifies your own boot image rather than displaying a prewritten screenshot. Change the string and rerun to establish that connection directly.
